# ADR-066: Platform-Aware Native Release Builds

- Status: Accepted for post-release implementation
- Date: 2026-09-14
- Related: ADR-043, ADR-065, SPEC-028, DF-029

## Context

The release builder originally forced `CGO_ENABLED=0` for the complete target
matrix. That policy is valid for a pure-Go artifact, but it excludes the
production macOS Keychain backend because its Security.framework integration is
implemented through cgo. A binary that compiles without its registered
production bootstrap backend must not be presented as a usable release artifact.

The supported matrix includes macOS Intel and Apple Silicon, Windows x64 and
ARM64, and Linux x64 and ARM64. Only macOS currently has an audited native
bootstrap backend. Darwin artifacts therefore require a Darwin SDK/toolchain and
cgo. Windows and Linux remain unsupported for production bootstrap packaging
until their governed native backends are implemented and qualified.

## Decision

The authoritative release builder owns a platform capability matrix. It shall:

1. select cgo per target rather than globally;
2. build Darwin targets with `CGO_ENABLED=1` and the native Security.framework
   backend;
3. refuse targets without an audited production bootstrap backend before
   replacing the requested output directory;
4. prove the required backend is present in the built artifact through a
   build-time capability-symbol check;
5. record target OS/architecture, cgo policy, bootstrap capability, qualified
   source, preparation source, and Go toolchain in each archive's metadata; and
6. allow an explicit target subset for qualification, while retaining the full
   supported matrix as the default release request.

Darwin amd64 and arm64 may be cross-compiled from a host with a compatible
Darwin SDK and C toolchain. The builder must not claim that a non-Darwin host
can produce those artifacts; toolchain failure is a release failure. Native
OS frameworks remain below the generic `BootstrapBackend` boundary and do not
alter GoalStore semantics.

The Makefile remains a convenience wrapper. It may pass an explicit target
subset to the authoritative builder but does not build release artifacts by a
second path. Checksums and provenance remain generated by the builder.

## Consequences

`make package RELEASE_TARGETS='darwin/amd64 darwin/arm64'` can qualify the
currently supported native backend on an authorized macOS toolchain. A default
full-matrix package request fails closed until Windows and Linux production
bootstrap backends exist. No weaker fallback, fake backend, or implicit crypto
profile is permitted.
